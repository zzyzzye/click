# ClickFlow 手动启用全局热键设计

## 目标

ClickFlow 启动时不注册、不占用任何全局热键。只有用户在“热键”页面明确打开
“启用全局热键”开关后，配置的开始/停止、坐标捕获、紧急停止、宏录制和宏回放
热键才生效。

## 用户体验

“热键”页面增加一个总开关和状态说明：

- 默认状态：“启用全局热键”关闭，状态显示“当前未占用任何系统热键”
- 开启成功：状态显示“全局热键已启用”
- 主动关闭：立即释放全部热键并恢复未启用状态
- 开启失败：开关自动恢复关闭，释放可能已注册的热键，并显示注册失败原因

开启状态只属于当前应用会话，不写入设置。每次重新启动 ClickFlow 都从关闭状态
开始，避免用户只是打开查看时影响其他应用。

## 生命周期

主窗口负责全局热键是否启用这一会话状态，平台热键服务只负责注册和释放：

1. 主窗口构造时加载上次配置，但不调用 `registerHotkeys`
2. 用户开启总开关时，先校验五组热键，再调用平台服务注册
3. 用户关闭总开关时调用 `unregisterAll`
4. 应用退出时由热键服务析构逻辑确保释放
5. 用户通过界面启动或停止连点时，不隐式开启全局热键

因此，关闭状态下仍可正常使用界面按钮进行连点，只是任何全局快捷键都不会响应。

## 编辑与预设

关闭状态下修改热键：

- 不调用平台注册接口
- 配置完整且校验通过时保存到最后使用配置
- 页面继续显示“当前未占用任何系统热键”

开启状态下修改热键：

- 校验通过后重新注册整组热键
- 注册成功后保持开启并保存配置
- 校验或注册失败时释放整组热键、关闭总开关并显示错误

加载预设遵循相同规则：关闭状态只加载配置；开启状态尝试用新配置重新注册，失败
时回退到关闭状态。不会保留一部分旧热键或一部分新热键。

## 页面状态同步

`HotkeySettingsPage` 提供开关事件和状态更新接口，`MainWindow` 持有真实启用状态并
协调平台服务。键鼠录制页面现有的热键状态提示同步显示注册结果，但 macOS 上录制
功能仍保持“不支持”状态，不扩大本次改动范围。

## 测试

主窗口测试使用假的热键服务验证：

- 构造窗口不会调用 `registerHotkeys`
- 构造完成后页面开关处于关闭状态
- 手动开启会校验并注册一次
- 手动关闭会调用 `unregisterAll`
- 关闭状态下修改热键不会注册
- 关闭状态下点击“开始连点”不会隐式注册
- 开启状态下注册失败会回退到关闭状态
- 加载预设时仅在开关开启状态重新注册

现有连点、宏、页面和平台热键测试必须继续通过。

## 成功标准

- 启动 ClickFlow 不占用任何全局热键
- 用户可以明确看到热键当前是否启用
- 只有主动开启后全局热键才生效
- 关闭或失败后不存在残留注册
- 界面按钮的连点功能不依赖全局热键开关
- 开启状态不会跨应用重启保存
