# ClickFlow 公共 README 重构设计

日期：2026-07-31
状态：已确认

## 目标

把 README 从面向单个开发环境的操作记录，重构为面向开源项目使用者、贡献者和维护者的项目首页。读者应能快速判断 ClickFlow 的用途、平台能力、安全边界、获取方式、构建方法和发布流程。

## 受众

- 使用者：了解功能、下载入口、默认控制方式和权限限制。
- 贡献者：了解技术栈、依赖、构建测试命令和主要平台差异。
- 维护者：了解版本来源、云端打包、标签和 GitHub Release 流程。

## 信息架构

README 按以下顺序组织：

1. 项目定位与 Releases 下载入口；
2. 核心功能与平台支持矩阵；
3. Windows 安装和未签名提示；
4. 键鼠宏的使用、安全与隐私说明；
5. 开发环境、Windows/macOS 构建和测试；
6. Windows 便携目录与云端安装包；
7. 面向维护者的通用发布清单；
8. 平台和权限限制。

## 写作规则

- 项目简介不硬编码当前版本，版本唯一来源仍是 `CMakeLists.txt`。
- 示例使用 `<version>` 或 PowerShell 变量，不绑定 0.3.0/0.4.0。
- 删除“你的电脑”“受限开发电脑”等特定用户或机器语境。
- 说明工作流的输入、输出和权限边界，但不过度描述内部排障历史。
- 不承诺尚未实现的自动更新、代码签名、macOS 宏录制或其他功能。
- 保留宏录制可能包含敏感输入、普通权限不能控制提权窗口等重要警告。
- 不添加不存在的许可证、贡献协议、截图或发布资产。

## 发布文档原则

- `project(ClickFlow VERSION x.y.z)` 是唯一产品版本源。
- 发布提交、`v<version>` 标签、Actions 构建来源和 Release 资产必须一致。
- Windows 安装包由手动触发的 `Windows 安装包` 工作流生成。
- 工作流基于发布标签运行，产出版本化 EXE 和 SHA-256。
- 标签和 GitHub Release 仍由维护者手动创建。
- 未签名安装包必须明确提示 SmartScreen 风险。

## 不在本次范围

- 修改程序功能、构建逻辑或安装器行为；
- 修改用户已经完成的 0.4.0 版本改动；
- 新增 LICENSE、CONTRIBUTING、截图或自动发布；
- 修改历史设计和实现计划中的旧版本示例。
