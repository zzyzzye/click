# Windows 键鼠宏录制与回放设计

## 目标

在 ClickFlow 中新增独立的“键鼠录制”功能，在 Windows 10/11 x64 上录制
整个系统的键盘与鼠标操作，并按原始节奏或指定速度重复回放。功能同时支持：

- 全局模式：记录跨应用、跨窗口的完整操作；
- 绑定窗口模式：选择一个目标窗口，只记录该窗口内的操作，并使用客户区
  相对坐标回放。

现有鼠标/键盘连点功能继续保留。连点、宏录制和宏回放共享一个独占运行状态，
任何时刻只能执行其中一种活动。

## 第一版范围

第一版包含：

- 键盘按下与抬起，包括普通键、功能键、修饰键和组合键；
- 鼠标移动、左/右/中键按下与抬起、拖拽、垂直与水平滚轮；
- 鼠标轨迹自动采样和压缩；
- 原速、0.5 倍、1.5 倍和 2 倍回放；
- 有限循环、无限循环及轮次间隔；
- 本机宏的保存、选择、重命名和删除；
- 可配置的开始/停止录制、开始/停止回放和紧急停止全局热键；
- 窗口列表与拖动准星两种目标窗口选择方式；
- 目标窗口、权限、尺寸和输入状态安全检查。

第一版不包含 macOS 支持、逐事件编辑、宏导入/导出、云同步、UI Automation
语义动作、后台向非前台窗口发送输入、管理员权限提升或对反作弊游戏的兼容承诺。

## 用户界面

左侧导航在“连点设置”之后新增“键鼠录制”页面。该页面分为以下区域：

1. **控制热键**：页面顶部始终显示三组宏控制热键及注册状态。录制或回放时，
   底部状态栏明确显示停止热键与紧急停止热键。热键冲突或注册失败必须使用
   醒目错误提示，不能静默降级。
2. **录制目标**：选择“全局”或“绑定窗口”。绑定窗口模式提供包含“窗口标题 +
   程序名”的下拉列表、刷新按钮和拖动准星选窗。ClickFlow 自身窗口不作为目标。
3. **录制管理**：显示宏名称、录制时长、事件数量、目标摘要，并提供新录制、
   停止、重命名和删除操作。第一版不显示或编辑逐事件时间线。
4. **回放设置**：速度、有限/无限循环、有限次数及每轮间隔。
5. **主要操作**：录制和回放使用不同按钮；当前状态为录制、回放或被其他自动化
   活动占用时，按钮文字和可用性必须同步更新。

宏控制热键默认使用 `F9` 开始/停止录制、`F10` 开始/停止回放，并与现有
`F6` 连点开始/停止、`F7` 捕获坐标和共享的 `F8` 紧急停止共同校验。所有全局
热键在设置页中明确标注用途，不能重复注册。

## 核心数据模型

`MacroEvent` 保存：

- 事件类型；
- 自录制开始后的单调时钟微秒数；
- 键盘虚拟键码、扫描码、扩展键标志和按下/抬起状态；或
- 鼠标坐标、按钮、滚轮增量和按下/抬起状态。

全局模式的鼠标坐标使用虚拟桌面物理像素。绑定窗口模式使用目标窗口客户区
左上角为原点的物理像素坐标；拖拽从客户区内开始后，允许保存客户区外的相对
坐标，以保证抬起事件完整。

`MacroSequence` 保存：

- 稳定 UUID、用户可见名称、创建与修改时间；
- 录制模式、总时长和事件列表；
- 绑定窗口的可执行文件路径、窗口类名、窗口标题和录制时客户区尺寸；
- 格式版本，用于以后兼容迁移。

回放速度、循环次数和轮次间隔属于本机的宏播放设置，与事件序列一起保存。

## 模块与职责

### `MacroRecorder`

跨平台核心接口只暴露开始、停止、状态和事件输出，不包含 Win32 类型。
`WindowsMacroRecorder` 在专用线程中安装 `WH_KEYBOARD_LL` 与
`WH_MOUSE_LL` 钩子。钩子回调只做时间戳、字段复制、内部注入标记过滤和快速
入队；压缩、窗口判断和持久化不在钩子回调中执行。

### `MacroPlayer`

`WindowsMacroPlayer` 将 `MacroEvent` 转换为 `INPUT`，通过 `SendInput`
回放。每个注入事件设置 ClickFlow 专用 `dwExtraInfo` 标记，录制器必须忽略带有
该标记的事件，防止回放被再次录制。

播放器跟踪由自己按下但尚未抬起的键和鼠标按钮。正常停止、紧急停止、注入失败
或应用退出时，播放器都发送配对的抬起事件，避免系统遗留“卡键”状态。

### `MacroController`

控制录制、轨迹压缩、回放调度、速度换算、循环和状态通知。回放使用基于绝对
目标时间的单次精确定时器；每次调度根据录制时间戳和速度重新计算目标时刻，
不通过累加延迟推进，从而避免长时间回放逐步漂移。

### `MacroRepository`

在 `QStandardPaths::AppDataLocation/macros` 中以每个宏一个版本化 JSON 文件的
方式保存数据，文件名使用 UUID，不直接使用用户输入名称。写入使用 `QSaveFile`
保证原子替换。损坏或不支持的文件跳过加载并显示可操作错误，不影响其他宏。

### `AutomationCoordinator`

统一拥有 `Idle`、`Clicking`、`Recording`、`Playing` 四种状态。连点控制器和
宏控制器开始活动前必须取得独占权；活动结束或失败后释放。紧急停止终止当前
拥有者，页面不能各自实现一套互斥判断。

## 录制流程

1. 校验控制热键、录制模式和可选目标窗口。
2. 从 `AutomationCoordinator` 取得独占权。
3. 安装钩子，记录单调时钟起点，并更新页面与状态栏。
4. 键盘事件保留物理扫描码和完整按下/抬起顺序。宏控制组合键视为保留键，
   从序列中成组移除，不能留下孤立的修饰键事件。
5. 鼠标按下、抬起和滚轮事件全部保留。移动事件最多约每 16 毫秒采样一次；
   极小位移和近似共线的连续移动在停止录制后合并。按住按钮拖拽时使用更保守
   的压缩阈值。
6. 停止时卸载钩子、完成压缩并验证按键/按钮配对。空序列不保存。
7. 用户命名后由仓库原子写入本机目录并释放独占权。

低级钩子只观察事件，不吞掉用户输入。录制必须由可见界面按钮或已标明的全局
热键主动启动，状态栏持续显示“录制中”、时长、事件数和停止方式。首次录制前
提示宏可能包含敏感按键，并建议不要录制密码；程序不尝试在后台隐蔽录制。

## 绑定窗口行为

窗口列表只显示可见、未被 DWM 隐藏且具有有效标题的顶层窗口，显示程序名与
标题。拖动准星释放时使用光标下窗口的顶层根窗口作为目标。

录制期间：

- 键盘事件仅在目标窗口或其所属顶层窗口处于前台时记录；
- 鼠标事件仅在目标客户区内记录；若一次拖拽在客户区内开始，则持续记录到按钮
  抬起，即使光标短暂移出客户区；
- 目标窗口关闭时立即停止并报告原因。

回放前根据当前句柄或保存的可执行文件路径、窗口类名和标题重新解析目标窗口。
无法唯一解析时要求用户重新选择。播放器尝试激活目标窗口；若 Windows 前台
切换限制阻止激活，则暂停并要求用户手动激活，而不是向其他窗口继续发送输入。

窗口位置可以变化，因为坐标相对于客户区。客户区宽高与录制值的差异超过
`max(8 像素, 2%)` 时禁止回放并提示恢复尺寸。第一版不自动缩放坐标，避免布局
变化后误点。应用使用 Per-Monitor V2 DPI 感知，跨显示器与不同缩放比例下统一
使用物理像素进行 Win32 坐标转换。

## 全局模式行为

全局模式记录虚拟桌面上的所有支持事件和前台窗口切换造成的自然输入结果，
但不保存屏幕画面或窗口内容。回放使用录制时的虚拟桌面坐标。若当前显示器布局
或虚拟桌面边界无法包含某个坐标，开始前拒绝回放并指出原因，不能把坐标静默
裁剪到其他位置。

## 回放与循环

回放前执行完整预检：宏非空、坐标有效、所有控制热键有效、没有其他自动化活动，
以及绑定窗口可解析、可激活且尺寸匹配。有限循环至少一次；无限循环必须始终可
被回放热键或紧急停止热键终止。

事件目标时间按 `recordedOffset / speed` 计算。每轮完成后等待配置的轮次间隔，
再从第一条事件重新开始。回放过程中不允许修改宏、速度、循环或热键设置。

回放热键和紧急停止热键优先于普通宏事件。停止后不再调度新事件，并先释放所有
播放器仍持有的键和按钮，再更新界面状态。

## 错误处理与安全边界

- 钩子安装失败：不进入录制状态，显示 Win32 错误摘要。
- `SendInput` 部分或全部失败：立即停止，释放已按下输入并提示可能存在 UIPI
  权限级别限制。
- 目标窗口关闭、失焦或尺寸变化：绑定窗口回放立即暂停/停止，不向其他窗口发送。
- Windows 锁屏、UAC 安全桌面或桌面切换：停止回放并释放输入。
- 普通权限 ClickFlow 不尝试控制管理员权限窗口，也不自动请求提升。
- 某些反作弊程序、游戏或受保护应用可能拒绝钩子或模拟输入；界面明确说明该限制。
- 应用关闭时按顺序停止控制器、卸载钩子、释放注入输入并注销热键。

录制文件包含按键码和时间，可能反映用户输入。文件只保存在当前电脑的应用数据
目录，不上传、不导出、不写入日志。第一版无法可靠识别浏览器或自绘控件中的
密码字段，因此依赖显式录制状态与首次安全提示，而不声称自动过滤密码。

## 测试策略

纯逻辑单元测试覆盖：

- 宏 JSON 的版本化序列化、往返恢复、损坏文件隔离与原子保存路径；
- 键盘、鼠标、滚轮事件转换及扩展键标志；
- 控制热键过滤不会留下孤立修饰键；
- 鼠标采样、直线压缩和拖拽保真；
- 速度换算、绝对时间调度、有限/无限循环和轮次间隔；
- 正常、失败和紧急停止时释放所有仍按下的输入；
- 全局坐标与客户区相对坐标转换；
- 窗口尺寸容差、窗口身份匹配和多候选拒绝；
- `AutomationCoordinator` 对连点、录制和回放的互斥；
- 五组全局热键的冲突校验与事务回滚；
- 页面持续显示三组宏控制热键及当前运行状态。

Win32 API 置于窄适配接口后，通过测试替身验证钩子安装/卸载、窗口枚举、前台
检查、坐标转换和 `SendInput` 调用，不在自动测试中移动真实鼠标或注入真实按键。

Windows 手工验收覆盖：

1. 在记事本中录制文字、组合键、点击、滚轮和拖拽，并以四种速度回放；
2. 录制跨记事本和资源管理器的全局宏并有限/无限循环；
3. 移动绑定窗口后成功回放，改变窗口尺寸后得到阻止提示；
4. 通过下拉列表和拖动准星分别选择目标窗口；
5. 在录制与回放期间验证 F9、F10 和 F8 提示及行为；
6. 尝试在连点、录制和回放之间并发启动，确认只允许一个活动；
7. 中途停止含按住键或拖拽的宏，确认没有卡键或卡住鼠标按钮；
8. 尝试控制管理员窗口，确认安全失败且应用保持可用；
9. 重启应用，确认本机宏及播放设置仍可加载。

## 验收标准

1. 用户能选择全局或绑定窗口模式，完整录制标准键盘和鼠标操作。
2. 录制结果能保存到当前电脑，并可选择、重命名、删除和跨重启加载。
3. 用户能以所选速度、循环次数和轮次间隔回放，停止后无遗留按下状态。
4. 三组宏控制热键始终在页面中明确显示，冲突时不能启动。
5. 连点、宏录制和宏回放严格互斥，共享紧急停止。
6. 绑定窗口移动不影响坐标，尺寸明显变化、窗口关闭或失焦时不会误操作其他窗口。
7. ClickFlow 注入的事件不会被录制器再次捕获。
8. 自动测试、Windows 构建和现有 ClickFlow 回归测试全部通过。
