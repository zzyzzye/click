# ClickFlow 1.0 发布前验收

本文用于验收现有功能，不代表已经正式发布 1.0。目标是确认安装、日常操作和更新闭环可用，不要求第三、四阶段的新功能全部实现。

## 已完成的本地检查

2026-10-11 的完善范围：连点启动前检查平台按键能力、固定坐标和显示器空隙；倒计时结束及运行中复查权限和布局；倒计时停止不被后续状态覆盖。流程编辑器补齐空状态、选择与排序边界、复制数量上限、单个组合键、保存状态和执行反馈重置。预设管理区分列表选中与当前使用的配置，修复重命名或删除其他预设误改当前配置关联，拒绝会形成嵌套设置分组的名称，并检查设置写入结果。更新仅匹配正式版本的准确附件名称与地址，失效附件回到重新检查入口。

这些路径使用临时数据、模拟网络、假输入后端和离屏 Qt 界面检查，不注入真实键鼠、不运行真实安装器。本地检查结果不能替代以下目标系统验收。

验证结果：macOS Debug 构建通过，完整 11 个 CTest 套件通过，新增 12 个回归测试方法。最终压缩流程页顶部布局后，Flows、ClickFlowPages、MainWindow 三个相关套件再次通过；最小 820×560 的添加按钮完整可见，820×560 与 960×680 的页面截图已检查。`git diff --check` 通过，修改过的流程及更新源文件 clang-format 检查通过。Frontend Design Premium 严格静态审查无发现；DESIGN.md lint 无错误，仍有 8 个既有设计令牌警告。Windows/Linux 原生构建、安装与真实输入尚未在本轮验证。

## Windows 验收

使用专用测试窗口和不含敏感内容的测试数据。先确认停止按钮可见；需要全局热键时，在“热键”页面启用并确认注册成功。

| 项目 | 操作 | 通过标准 |
|---|---|---|
| 安装 | 分别在 x64、ARM64 系统安装对应包，打开开始菜单和控制面板 | 程序启动正常，图标和版本正确，只有一个卸载项 |
| 连点 | 有限 3 次、无限后停止、倒计时中停止、键盘连按 | 次数正确，停止后不再输入；与已启用控制热键冲突时拒绝开始 |
| 坐标与权限 | 固定点、负坐标副屏、屏幕空隙、移除显示器或撤销权限 | 无效目标不执行；条件变化后停止并说明恢复方法 |
| 录制 | 录制点击、文字、滚轮和拖拽；停止、试运行、取消命名、保存后重开 | 草稿不因取消而丢失，试运行一轮，保存后回放内容一致 |
| 编排 | 点击 → 文字 → Enter → 等待 → 点击，执行 2 轮；等待中暂停、继续、紧急停止 | 顺序、轮数、等待正确；暂停期间无新输入；停止后重新开始从头运行 |
| 编辑与保存 | 复制、移动、删除、撤销、重做；未保存时新建或关闭并取消 | 内容和顺序正确，取消保留修改，重开保存文件内容一致 |
| 预设 | 使用 A，选择 B 后重命名或删除 B，再保存 A；重命名当前 A 后重开软件 | B 的管理不改变 A；不会把 A 参数写入 B；最近使用的名称正确 |
| 窗口与滚动 | 最小窗口、系统缩放、鼠标悬停数字框和下拉框滚动、键盘导航 | 停止入口始终可见；字段可到达，滚轮不误改参数 |
| 卸载 | 在测试账户卸载，检查卸载项、快捷方式、安装目录和应用数据 | 符合项目卸载约定；与更新的数据保留行为区分清楚 |

## Windows 覆盖更新验收

1. 安装包含更新机制的较低版本 A；不能使用未注册的便携副本或开发目录代替。
2. 保存测试配置、预设、录制及流程。记录安装目录和控制面板条目。
3. 准备更高版本 B 的正式 GitHub Release，包含对应架构安装包与 `.sha256`；草稿和同版本不能用于发现新版本。
4. 在 A 的“预设与关于”中检查、下载。检查进度、取消后重新下载、断网后重试。
5. 下载完成后先继续使用 A；只有点击“重启并更新”才退出。未保存确认选择取消，应留在 A 且保留更新包。
6. 点击重启更新并取消一次 UAC，确认旧版本重开；随后重新下载、同意授权，确认覆盖后自动重开 B。
7. 检查原目录、快捷方式、唯一卸载项、版本号及四类用户数据。安装失败只要求正确提示并尝试启动可用版本，不把自动回滚列为已有能力。

记录每项实际系统、版本与结果。没有运行的项目保留“待验证”，失败项目记录重现步骤；Windows 的 UAC、覆盖安装、卸载和真实输入验收完成后，再决定正式发布 1.0。
