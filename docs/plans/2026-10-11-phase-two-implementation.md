# 第二阶段：步骤编辑、多点编排与运行控制

状态：第二阶段工程实现与本地自动化验证完成；目标系统实际输入和新用户观察待进行。

## 实现范围与所有者

- `FlowDocument` / `FlowStep` 表示流程与稳定步骤标识；多点就是多个点击步骤，不另建配置类型。
- `FlowRepository` 使用 `ClickFlow.Flow`、版本 1 和原子文件写入，保存顺序、参数、循环和屏幕布局。未知版本与未知步骤拒绝读取，损坏文件提示后跳过。
- `FlowTypes::compile` 转换为共用事件时间线，不新增多点调度器；`MacroController` 负责批次调度、循环、暂停、剩余等待、停止和进度。
- `FlowPlayer` 将手工动作适配到已有 ClickBackend，原始事件适配到 Windows MacroPlayer。暂停释放原始模拟输入；继续前重新验证权限、布局及绑定目标。
- `FlowEditorPage` 使用原生 Qt 控件，实现插入、复制、删除、上移下移、最近 50 次撤销重做、属性编辑、空状态和固定底部控制区。
- `FlowWorkflowController` 管理保存、新建、打开、单轮试运行、坐标捕获与未保存确认。自动化执行权始终由 AutomationCoordinator 统一分配。

## 行为约定

点击步骤包含屏幕坐标、左/右键、次数、执行后等待；连续点击间隔 10ms。文字按 Unicode 字符分批发送，不写入日志，文件中明文存储。等待使用异步计时器，不阻塞 UI；暂停后保留剩余等待，不补发暂停期间的事件。手工等待从前一个动作实际完成后计时，即使系统繁忙导致动作延迟，也不会压缩等待来追赶原时间线；原始录制块保留自身事件节奏。

整体有限/无限循环及轮次间隔复用宏配置。单轮试运行使用独立快照，不更改保存设置。执行总是从步骤 1 开始，只有暂停继续保留当前位置。进度展示当前步骤、轮次和完成轮数，无限循环不显示百分比。原始事件只在步骤变化时更新步骤界面，不逐个重绘。

原始录制无损放入完整事件块，保留事件及回放速度；暂停请求等到块结束，不支持拖拽中途恢复。已保存旧宏文件保持原样，因此无需原地升级或覆盖备份；新流程保存为独立文件，可直接回到原宏。未保存录制草稿转移到编辑器后，由流程的未保存确认接管。

绑定窗口的原始录制首期只能搭配等待；同一流程的多个录制块必须使用同一目标。避免把客户区坐标当作屏幕坐标。暂不开放嵌套循环、分支、块内原始事件编辑或从选中步骤执行。

新建、打开其他流程和关闭窗口前提供保存、放弃、取消；取消或保存失败保留编辑内容。切换侧栏页面不销毁内容，因此不反复询问。关闭先停止输入，取消关闭也不恢复输入。捕获按钮延迟 3 秒，支持底部停止和紧急停止取消；F7 可立即捕获所选点。

默认 F11 暂停/继续，加入所有平台整组热键注册、持久化、冲突校验和录制保留热键。热键需用户手动启用。流程运行或暂停时，连点和录制互斥；跨页面紧急停止有效。

## 平台边界

Windows 复用原始录制后端；新增手工左/右点击、常用按键组合和 Unicode 输入。macOS 复用已有点击后端，增加常用按键组合和 Unicode 输入；字母/数字组合键使用标准物理键位，文字步骤不依赖物理键位。Linux X11 首期支持点击、等待和现有单键范围，不启用组合键或文字，Wayland 不支持。所有不可执行能力在启动前提示，不能先执行前半段再发现不支持。

点击启动前逐点检查屏幕范围和屏幕布局快照；输入动作间按步骤或每 250ms 复查布局/权限。缩放和目标应用界面改变仍需用户重新检查和捕获点位，不承诺自动跟踪控件。Linux 使用 XRandR 活动显示器矩形识别屏幕间空隙；无法读取布局时拒绝启动点击流程，构建依赖增加 libxrandr-dev。
