# ClickFlow 自动化功能演进计划书

日期：2026-10-10

状态：第一、二阶段工程实现与本地自动化验证已完成，第三、四阶段待实施；新用户观察和目标平台实际输入验证待进行

基线：当前 0.5.1 项目能力；本文不代表版本发布承诺。

## 1. 产品目标

将 ClickFlow 从连点与键鼠录制工具，逐步扩展为无需编程的桌面自动化工具。用户可以录制操作、编辑步骤、观察执行进度，并在中断后继续执行。

借鉴 AutoHotkey 的快捷操作与流程自动化思路，优先采用可视化配置。暂不开发脚本语言，也不承诺兼容或直接运行 AHK 脚本。

典型流程：点击输入框 → 输入文字 → 按 Enter → 等待 2 秒 → 点击确认 → 循环 10 次。

### 首次使用流程优先

以用户要完成的任务组织三个入口，名称为规划用语，实施时再结合界面验证：

| 入口 | 默认操作路径 | 高级选项 |
|---|---|---|
| 快速连点 | 选择鼠标或键盘 → 设置间隔 → 开始 | 有限次数、固定位置、抖动、倒计时 |
| 录一遍，自动重复 | 开始录制 → 完成操作 → 停止录制 → 试运行 → 保存 | 目标窗口、速度、循环 |
| 自己编排步骤 | 添加点击/按键/文字/等待 → 调整顺序 → 试运行 → 保存 | 应用条件、条件等待等后续能力 |

- 多点点击是编排步骤中的快捷创建方式，生成多个点击步骤，不新增独立的流程体系或重复页面。
- 录制结果与手工步骤进入同一个编辑器；录制完成后无需先命名或保存即可试运行。
- 首次录制先简短说明范围和停止方式。权限缺失时给出具体处理入口，并保留当前配置。
- 高级设置按需展开，默认显示完成当前任务所需的内容；快捷键是辅助入口，不作为使用前提。
- 试运行默认执行一轮，明确提醒即将操作真实桌面；运行前可取消，运行中随时可停止。
- 运行控制位于固定区域：空闲时“开始”，运行时“暂停”和“停止”，暂停时“继续”和“停止”。录制状态使用“停止录制”，不混用含义。
- 停止后再次开始从头运行；只有暂停后的继续保留执行位置。暂停期间仍占用自动化执行权，不能启动另一个任务。
- 区分“连点设置已自动保存”“流程尚未保存”和“流程已保存”，禁止用一个笼统的“已自动保存”覆盖所有状态。
- 离开未保存流程时提供保存、放弃和取消；错误提示说明原因和下一步，不只显示错误码。
- 不支持的功能显示平台原因及可用替代入口，不能只显示没有解释的灰色按钮。

首次使用验收：邀请未参与开发的人，不口头指导，观察其能否完成一次连点；在支持录制的平台上，能否跟随页面完成录制、试运行和保存。记录卡住的位置、误操作与是否需要求助；未完成时修正交互后再验收，不能仅增加说明书。后续步骤编辑也按同样方式验证。

## 2. 当前能力与边界

- 三个平台已有自动连点、全局热键和配置预设；支持有限次数、无限循环及启动倒计时。
- Windows 已有全局键鼠录制与回放、目标窗口绑定、速度调整、循环与轮次间隔。
- 已有紧急停止和运行状态协调，应继续复用。
- macOS、Linux 尚未具备键鼠宏录制与回放；Linux 全局输入目前限 X11，不能把打包支持等同于功能完全一致。
- 本计划中的编辑器、多点点击、暂停继续等属于拟新增能力。

### 重叠能力的处理

- Windows 录制宏已能表达多个位置的点击。多点功能补充手动编排体验，复用执行能力。
- 点击计数与宏事件进度已有信号；进度功能扩展展示、轮次和错误定位，复用现有统计。
- Windows 已有目标窗口绑定；应用匹配在此基础上扩展，避免另建窗口选择逻辑。
- 循环、等待、停止和热键校验复用现有能力；统一行为后再扩展暂停，不新增第三套调度器。
- 流程文本输入与全局缩写展开分开排期，首期只实现前者。

## 3. 功能清单

| 功能 | 用户收益 | 优先级 | 首期范围 |
|---|---|---|---|
| 可视化步骤编辑器 | 局部修改录制结果，减少重新录制 | P0 | 添加、修改、删除、复制、排序步骤 |
| 多点点击 | 顺序执行多个位置的点击 | P0 | 编辑器中的快捷编排、独立等待时间、整体循环 |
| 暂停与继续 | 临时中断后继续操作 | P0 | 执行阶段暂停，录制阶段不纳入首期 |
| 执行进度 | 了解正在执行什么以及完成多少 | P0 | 当前步骤、轮次、已完成次数、停止原因 |
| 配置导入与导出 | 备份、迁移、分享流程 | P1 | 版本化文件、导入预览、冲突处理 |
| macOS/Linux 宏能力 | 扩大可视化流程的可用平台 | P1 | 分平台补齐基础回放，再评估录制 |
| 窗口条件等待 | 等待应用就绪，减少固定延迟造成的失误 | P1 | 等待窗口出现或激活、超时停止 |
| 按应用切换配置 | 减少手动切换，限定快捷键作用范围 | P2 | 前台应用匹配、明确显示生效配置 |
| 找图、找色后执行 | 根据界面状态执行，减少固定延迟依赖 | P2 | 指定区域、超时、失败停止 |
| 文字快捷输入 | 快速填写常用文本 | P3 | 先支持流程中的文本步骤，再评估全局缩写展开 |

P0 为第一轮核心工作，P1 为后续完善，P2/P3 在核心体验稳定后推进。具体版本号与工期在实现前确认。

## 4. 分阶段交付

### 阶段一：统一模型、执行状态与操作流程

进展：已完成职责与复用边界梳理、共享模型和状态约定、现有执行边界修复、录制草稿操作闭环与本地回归。具体实现及验证边界见 [第一阶段设计](2026-10-10-phase-one-design.md)。新步骤模型、暂停与多点调度在第二阶段接入实际调用方。

目标：先确定三个入口的操作流程和共用执行语义，再开发编辑器与多点能力，避免先建设独立多点系统再重构。

- 梳理 ClickController、MacroController 和平台输入接口的职责，保留现有简单连点入口与兼容行为；统一可复用能力，不强行重写所有稳定代码。
- 定义高级步骤与原始事件块的关系，避免用户删除单个释放事件导致按键状态不完整。
- 确定坐标空间、次数与轮次、等待、暂停、继续、停止和失败语义，以及版本化保存格式。
- 检查宏回放积压时连续补发到期事件的行为；用假后端验证事件批次上限、停止响应及计时策略，不将风险当作已确认故障。
- 在界面开发前用操作流程稿走通首次使用、权限缺失、未保存离开和执行失败路径。

验收标准：旧连点与宏行为回归通过；共用执行接口与数据兼容方案明确；首次使用流程无必须理解的底层术语；不会增加一套独立多点调度器。

### 阶段二：步骤编辑、多点编排与运行控制

进展：步骤编辑、多点顺序执行、按键与文字、独立保存、运行进度及暂停继续已实现。平台支持与验证边界见 [第二阶段实现说明](2026-10-11-phase-two-implementation.md)。

目标：让录制与手动编排共用编辑器、执行进度和运行控制。先交付点击与等待的最小闭环，再扩展按键与文字。Windows 复用已有宏后端，其他平台按已验证的输入能力逐项启用。

- 支持添加坐标点，使用现有坐标捕获能力；每个点可设置鼠标按键、点击次数、执行后等待时间。
- 支持编辑、删除、复制、上移与下移；拖动排序作为增强交互，必须保留按钮或键盘操作。
- 复用有限/无限循环和紧急停止；明确“一轮”为完整执行一次点位列表。
- 显示当前点位、当前轮次和完成轮数。无限循环不显示虚假的百分比。
- 增加暂停/继续入口和可配置热键，纳入现有热键冲突检查。

验收标准：

- 三个点位按既定顺序执行，独立等待时间和整体循环均生效。
- 空列表、无效坐标、显示器布局变化有明确处理，不静默执行错误位置。
- 暂停后不产生新输入；继续前重新校验运行条件。紧急停止在暂停状态下仍有效。
- 暂停时释放已按下的模拟键鼠；首期仅在完整动作边界暂停，不支持拖拽中途恢复。
- 等待可被停止/暂停打断，UI 不因等待阻塞。继续时保留剩余等待时间。
- 保存与重新打开后，点位顺序、参数和循环配置一致。

编辑器范围：

- 提供步骤列表与属性编辑区，支持新建流程及打开录制结果。
- 首期手动步骤包括点击、按键组合、输入文字、等待；复用流程级循环，暂不提供嵌套循环和分支。
- 支持插入、复制、删除、调整顺序、撤销与重做；未保存离开时提示处理。
- 录制中的移动、滚轮、拖拽与按下/释放事件必须无损保留。首期对不能安全编辑的事件显示原始事件说明，不强行合并成高级步骤。
- 运行时锁定会影响执行内容的编辑，显示当前步骤和停止原因。
- 默认从流程开头运行；“从选中步骤开始”留待后续评估，避免遗漏前置状态。

验收标准：

- 能创建并保存“点击 → 输入文字 → Enter → 等待 → 点击”的流程，重新打开后内容一致。
- 修改等待时间和顺序后，执行使用修改后的内容。
- 现有宏打开、未修改保存、重新回放的行为保持兼容；旧数据升级前保留备份。
- 无效步骤在运行前定位并提示；执行失败显示步骤编号、原因和可采取的操作。
- 测试覆盖空流程、非法参数、快速停止、多轮执行和编辑撤销。

### 阶段三：导入导出与平台补齐

- 分别明确连点预设、多点配置和宏流程的数据类型，使用带格式版本的文件。
- 多点是流程的一种创建方式，保存和导出使用同一流程格式，避免产生第三种互不兼容的文件。
- 导入前展示名称、步骤数和所需平台能力；同名时可另存为新名称，不直接覆盖。
- 分享文件不自动执行；缺失图片资源或不支持的步骤给出清晰提示。
- macOS 先评估权限与基础回放，再补齐录制；Linux 先面向 X11 实现，Wayland 单独调研。
- 对不支持的能力显示原因，避免用户保存一个当前平台无法运行的流程而不知情。
- 增加窗口出现/激活条件等待，允许设置超时且可被暂停和停止打断；比找图更早验证条件驱动的执行方式。

验收标准：导出再导入后配置一致；损坏文件、未知格式版本和不支持能力均能正常报错，且不破坏已有数据。平台能力必须经过对应系统验证后才能标为支持。

### 阶段四：条件自动化与应用配置

- 找图/找色步骤明确搜索区域、匹配条件、等待上限；首期失败停止，后续再考虑重试或分支。
- 匹配多个位置时采用明确规则，提供预览；屏幕缩放、多显示器、主题变化纳入验证。
- 评估控件定位的可行性和平台边界；不能把找到窗口等同于找到按钮，也不能承诺找图适用于所有应用。
- 前台应用匹配优先使用稳定应用标识，窗口标题匹配作为可选条件。
- 仅在空闲时自动切换预设；运行中不悄悄替换流程。当前生效配置保持可见。
- 文字输入先作为流程步骤实现；全局缩写展开与按键重映射另行设计。

## 5. 实现原则

- 共享流程模型、校验、执行状态与持久化；通过平台接口完成输入、录制、窗口查询和屏幕获取。
- 点位配置可转换为共享执行步骤，避免创建两套循环、暂停和停止逻辑。
- 区分空闲、运行、暂停、停止中和失败状态；沿用录制、回放、连点互斥约束。
- 执行等待与输入调度不阻塞 UI；高频鼠标事件不逐条触发界面重绘。
- 数据格式显式版本化；未知步骤不能静默丢弃，升级与回退策略先于修改旧格式。
- UI 沿用现有品牌与 DESIGN.md；状态文案、热键提示和减少动态效果设置保持一致。
- 文本步骤不得将内容写入运行日志；导出前提示用户检查流程中的敏感内容。

## 6. 验证与发布

- 使用假输入后端验证步骤顺序、参数、循环、暂停恢复、停止响应和错误传播，日常测试不启动真实桌面输入。
- 对持久化与导入导出进行往返、旧版本兼容和损坏文件测试。
- 对编辑器进行最小窗口尺寸、滚动、键盘操作、禁用状态和减少动态效果检查。
- 将上述首次使用观察纳入验收，核对开始/暂停/继续/停止、试运行和保存文案是否符合实际行为。
- 在目标系统上用专用测试窗口验证真实输入、权限、窗口失焦及多显示器行为；未验证项明确记录。
- 每个阶段独立可交付，复用现有 GitHub 五种安装包流程。发版时按 AGENTS.md 准备版本与中文发布说明。

## 7. 首轮实施顺序与暂缓范围

首轮顺序：首次使用流程稿与现有能力去重 → 统一步骤模型和运行状态 → 共用编辑器中的点击/等待与多点编排 → 暂停继续与进度 → 扩展按键和文字 → 易用性验证与回归 → 导入导出、平台补齐与窗口条件等待。

暂缓：AHK 脚本兼容、自研脚本语言、嵌套条件编程、OCR、云端流程同步、插件市场及 Wayland 全局输入。后续根据真实使用需求调整。

第一、二阶段已包含应用优化；本次第二阶段未调整版本号，未自动提交或推送。后续阶段按范围分别实施与验证。
