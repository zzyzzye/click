# 第一阶段：现有执行逻辑优化与共享设计

状态：第一阶段工程实现与本地自动化验证完成。本文保留第一阶段设计记录；步骤模型及暂停状态现已在 [第二阶段](2026-10-11-phase-two-implementation.md) 实现。尚未做真实 Windows 输入验证或新用户观察。

## 当前职责与复用边界

- ClickController 管理简单连点的倒计时、计数和计时器；保留轻便入口。
- MacroController 管理录制结果、事件时间线、速度和轮次。
- AutomationCoordinator 管理连点、录制、回放的互斥和紧急停止。
- MacroPlayer 与平台服务负责注入及窗口校验；不将 Windows 输入标识直接推广为跨平台步骤。
- MacroWorkflowController 管理内存草稿、显式保存、试运行和覆盖/关闭确认；录制完成不再强制命名。

本轮先限制到期事件每批最多 64 个，后续批次至少让出一个计时周期，并在进度通知后检查是否已停止。保留事件顺序，不丢弃按键或鼠标释放事件。严重积压的最大允许延迟和失败策略留待真实平台验证后确定，不承诺毫秒级精度。

## 共享流程模型约定

| 概念 | 职责 |
|---|---|
| FlowDocument | 格式版本、标识、名称、步骤、运行配置；不保存临时运行状态 |
| FlowStep | 点击、组合键、文字、等待、原始录制事件块；使用稳定步骤标识 |
| TargetSpec | 跟随鼠标、屏幕坐标、窗口客户区坐标；窗口绑定由平台能力解析 |
| RunOptions | 有限/无限轮次、轮次间隔；一轮为完整流程 |
| RunSnapshot | 当前状态、步骤、已完成轮数、失败原因；供界面统一展示 |
| PlatformCapabilities | 声明当前平台能执行的步骤与定位方式，运行前统一校验 |

多点快捷创建生成点击与等待步骤，使用同一文档格式。录制导入先保留原始事件块，不擅自将任意按下/释放序列合并为点击。文本步骤独立于键码事件，平台实现与字符输入策略另行验证。

首期不替换旧宏 JSON。新格式必须有单向转换、原文件备份和未知版本拒绝策略；未编辑的旧宏继续走现有回放。没有兼容测试前不写回旧文件。

## 状态与执行规则

- 空闲 → 校验 → 运行；校验失败留在空闲并给出原因。
- 运行 → 请求暂停 → 完整动作边界暂停；界面不得提前宣称已经暂停。
- 暂停 → 重新校验目标 → 继续；目标失效则失败停止。
- 运行/暂停 → 停止中 → 释放模拟输入 → 空闲；失败保留错误信息，完成保留完成统计。
- 暂停仍持有执行权；录制、连点与流程始终互斥。
- 停止后开始从头执行；继续仅适用于暂停。等待恢复使用剩余时长，不补发暂停期间的事件。
- 原始事件块存在持续按键或拖拽时，首期不提供中途暂停恢复；紧急停止始终可用并释放输入。
- 未来共享执行器只管理步骤调度，平台接口只执行动作；不创建独立多点调度器，也不强行将简单连点转成巨大事件列表。

## 首次使用流程稿

1. 快速连点：默认可用设置 → 修改间隔 → 开始 → 查看计数 → 停止。固定坐标等选项按需展开。
2. 录制重复：说明录制范围和停止方式 → 开始录制 → 停止 → 展示未保存草稿 → 一轮试运行或保存。取消命名不丢弃草稿。
3. 编排步骤（第一阶段时为流程稿，第二阶段已实现）：空状态说明 → 添加点击/等待 → 设置位置与时长 → 一轮试运行 → 保存。多点操作复用这一入口。

切换页面不销毁草稿；关闭窗口或重新录制时提供保存、放弃、取消。连点自动保存仅指连点设置。首次使用前的确认说明会操作真实桌面，可以取消；试运行入口也保留说明，执行中停止入口始终可见。不支持录制的平台解释原因并引导至连点设置。

已实现：连点页收起抖动、倒计时和置顶，加载非默认高级参数时展开；录制页流程引导、固定底部操作区、全局模式隐藏目标窗口；未启用热键时提示可用按钮，不显示虚假的冲突错误。

草稿取消命名与保存失败后保留，关闭取消时保留草稿但不恢复输入；显式放弃才删除内存草稿。没有新增敏感录制内容的自动落盘机制，异常退出无法恢复草稿。
